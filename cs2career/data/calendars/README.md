# 1.6.0 赛事日历维护

`2024.json`、`2025.json`、`2026.json` 是互相独立的真实届次精选日历。
不再把 2026 赛程改个年份用到所有年代，也不再生成虚构的历史 Play-In。
当前分别收录 26、39、48 场；这是游戏用的精选日历，不声称收齐现实全年所有比赛。

## 哪些是真实资料，哪些是模拟

- 名称与 `window`（该届赛事整体日期范围）按 `source_ids` 核验；网页地址在 `sources.json`。
- 主办方公布的完整日期可能包含公开预选、线上赛和线下决赛。游戏没有假装每一天都是真实转播日。
- 2024 Major 为 24 队、两个瑞士轮阶段；2025/2026 为 32 队、三个瑞士轮阶段，之后八强淘汰赛。
- 实际参赛名单随生涯变化；邀请名额、地区合并、非 Major 的紧凑赛制、奖金分配和对阵为游戏模型，不是历史数据库。
- 日期加载器把足够数量的赛制槽位排在真实开幕至闭幕之间，允许同一天多个轮次，不把比赛开幕提前到官方范围以外。
- 2025 Austin 保留 MRQ 晋级关系；“2025 后没有 RMR”不等于“2025 Austin 没有预选”。Budapest/2026 Major 使用其对应的直接邀请模型。
- 北美与南美在现有世界模型里共用 AM，Oceania 合并到 AS；后者条目有 `source_region` / `simulation_note`，不能声称精确复刻了现实地区规则。
- 部分奖金取现实公开金额，其他为同层次游戏值。运行时 `provenance.verified_fields` **只保证名称和实际日期**，不要把其他字段包装成已逐项核验的数据。

## 修改方法

修改对应年份 JSON 的 `events`。新增条目至少提供：

```json
{
  "id": "stable-edition-id",
  "name": "主办方公布的真实赛事名称",
  "type": "t2",
  "region": "EU",
  "regional_only": true,
  "window": ["07-01", "07-03"],
  "source_ids": ["在 sources.json 中定义的来源键"]
}
```

这是结构示例，不是已核验赛事，不能照抄到历史正式包。
`type` 为 major/t1/t2/qual/cct。预选赛设置 `feeds` 指向同年正赛 ID，`qualify` 表示模拟晋级名额。
地区预选应明确 `scope: "regional"`；普通地区杯使用 `regional_only: true`。
加载器检查 ID 唯一、日期有效、年份一致以及预选赛早于其晋级目标。

入口为 `cs2career.league.calendar.calendar_for(year)`。
上一级 `calendar.json` 仅为索引，不再是可直接读取的单年赛事列表。
扩展包的 events 接口保留，MM-DD 随当前年份展开；写明完整年份的条目不会被擅自改成年年举办。

2027 起尚未维护已核验包，自动生成的未来赛事明确带“模拟”标识及
`provenance.status = future_simulation`，不会捏造真实品牌已经公布了某届赛事。
若补充已公布的未来真实日历，需要把年份加入 `VERIFIED_YEARS` 并添加相应数据与来源。

## 旧存档

仅更新未开始、尚无比赛的未来赛事。已经完成或有比赛记录的赛事保留原样，
不改变比分、奖项、奖金、已启动 CS2 的比赛或历史阵容；历史中的旧名称不会被事后伪装成真实名称。
升级时不补打已经错过的赛程；替换了届次的旧邀请和报名会被撤销并重新发送合格邀请。
ApplicationState 在落盘前备份原 season/career 文件，不要求新建生涯。

## 来源与核验范围

优先使用 PGL 新闻室、ESL Pro Tour 公告、BLAST 赛事页面、完美世界和 StarLadder 官方公告；
CCT 日期使用 CCT 官方 Season 3 公告和 2026 日历。
2024 CCT Season 2 Europe Series 1 与 ECL Season 47 的地区日期也使用 HLTV 历史赛事页交叉核验，并明确保留地址，
其余不是靠名字规律猜测序号。

这些包不复制主办方文章正文、图片或商标素材，只记录赛事名称、日期和来源链接。
更新日期：2026-09-27。

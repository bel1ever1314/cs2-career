# 战术终点留守（tactics.20）

问题来自最近的 Inferno CT 路线：四名队友各只有一个 20 秒节点。
此前最终计时结束就移除路线控制者，随后原生 AI 会重新决策。日志中的
等待阶段速度为 0，hurryRemaining 也为 0，不能将其描述成“守点期间一直强制 Rush”。

## 参考与取舍

- [Bot Improver 正常配置](https://github.com/ed0ard/CS2-Bot-Improver/blob/main/cfg/my_bot_normal_config.cfg)
  关闭防守随机开局 Rush；本机此前已是 `bot_defense_rush_chance 0`。
- [CS2-Bot-Nav](https://github.com/ed0ard/CS2-Bot-Nav) 将 Hold 与 Release 分开。
  借鉴这个任务区分，复用本项目已适配的输入控制；不引入新的底层插件或内存偏移。
- 不将 Aggression 100 解释为 100% Rush，也不改选手能力、枪法、购买模板。

## 数据与执行

每个槽新增可选 `finish`：

- `auto`（旧库缺省）：按本回合实际阵营，CT 留守终点，T 恢复原生行动。
- `hold`：留守终点。
- `native`：最后等待结束后恢复原生行动。

旧库无需迁移或重画。中途 0 秒经过点仍连续通过，正数等待仍按原计时推进；
只有终点启用持久任务。终点为 0 秒也必须真正到达才保位，没有巨大计时器，
不会把 Stage 推出数组后继续索引。被物理位移推出范围会重新寻路，不强写位置。

保留原生感知和射击，接敌时释放观察朝向；受伤／避雷交还原生行为，无线电立即
释放，下包取消原路线转守包／回防，死亡、接管、换边、回合结束清理控制。
终点明确留守的持包人拿出 C4 或 Bot 开始拆包时释放任务，且不排队延迟 Idle。
空路线不受控；未接收自定义战术的 Bot 仍使用上游原生决策。

3D 和桌面编辑器均可选择结束方式，导入／导出／复制路线保留该字段。
日志增加 `custom_final_hold_started`，和普通限时等待区分。

## 验证

离线覆盖终点 20 秒到期后持续守位、明确释放、T/CT 换边、0 秒终点、
中途节点、位移接续、炸弹任务接管、严格 JSON 和旧库缺省。
沿用受伤避险、无线电与下包回归，以及 3D 编辑／发布／按钮反馈检查。
实机重点：沿用 Inferno 原 CT 战术，20 秒后不擅自前压；发无线电能立即解除。

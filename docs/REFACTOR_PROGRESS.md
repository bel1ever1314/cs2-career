## 新功能边界

1. 页面接收投影、发操作意图，不维护第二份生涯规则，不直接改宿主内部状态。
2. 服务协调业务，HTTP 适配器负责认证、参数和响应；新业务不要继续放进启动脚本。
3. 普通写入口进入 `ApplicationState.operation()`，必要时显式 `settle()`；内部保存会合并，查询不调用它们。
4. CS2 启动、安装、外部库存导出不可随内存回滚。必须独立持久化意图和结果，并实现恢复。
5. 历史不能原地修改，展示加工先复制。手动存档／备份展开归档引用，脱离原目录也可恢复。
6. 新行为先加临时存档测试和确定性种子，身份与安全令牌仍随机；自动回归不启动真实 CS2。

## Opus 复核跟进 · 同日第二批

- `CommitPending` 改为直接继承 `Exception`，不再落入普通 `OSError` 回退。检查了 HTTP、3D 适配器、天梯提交、手动存档、桌面命令及外围文件操作的捕获路径；补齐 3D／旧网页 catch-all 的显式传播，以及天梯模拟在已提交后不恢复旧内存的分支。
- HTTP 用 `503 + error_code=storage_recovery_required` 表示提交待恢复。状态锁内拒绝后续写入，读取也不投影半恢复内存。桌面拥有的后台先回复，再停止服务；退出不再次保存。Godot 重启自己的后台、读取新握手，再查原请求回执，不重发命令。外部启动的后台只提示重启，不替用户杀进程。
- 回执保留 30 天／最多 2,048 条，并增加结果 8 KiB、单条 12 KiB、整组 1 MiB 上限。小结果保留原格式；大结果明确标注 `result_summary`，保留成功状态、简短提示、关联编号。读取旧回执只生成精简副本，下次新命令提交才缩减存储；不改比赛历史。前端确认摘要后不自动推进快速赛季或重放旧动画，完整战报仍在比赛记录。
- 正常比赛中断用 `MatchPaused` 明确表示，HTTP 接受为 `ok=true/status=paused` 并保存剧情。移除了“任何模拟 ValueError，只要已有剧情就视作成功暂停”的宽泛处理。3D 原有返回 `paused` 的正常分支继续提交；普通拒绝仍整体回滚。旧桌面同样识别这类正常暂停。
- 只读历史支持 `copy.copy` 和各版本 pickle 协议。浅复制返回普通容器、共享只读子项；pickle 往返返回可编辑的普通字典／列表。不增加读取 pickle 存档的入口。
- 只读长期存档测量：该存档没有新式集中回执。其最大单场记录构成的测试响应为 514,669 字节，确认回执为 202 字节；这是用真实报告形状构造的样本，不声称老存档已发生回执膨胀。

## 设置、开局与回执合并 · 第三批

- 配置写入复用存档事务。新增 `transaction.read_bytes()`，同一请求构建响应时能读到待提交配置，其他线程仍读取已提交文件。它只用于小配置，不用来反复序列化整份生涯。恢复顺序调整到配置导入／自动填充之前，避免启动时先覆盖尚待恢复的配置。

- 创建角色先在新对象上设置快速模式和继承偏好，再替换生涯。生涯数据、开局回执、HTTP 回执和版本号一起提交。创建拒绝不消耗草稿；提交后、草稿收尾前中断则在下次启动补完。

## 比赛工作流与逐图提交 · 第四批

- 拆出 `services/match_launch.py`、`match_simulation.py` 和 `season_run.py`。HTTP 只鉴权／传参／返回；协调器负责提交顺序，领域层保留原 BP、阶段剧情、比分和奖励规则。三类工作流主动拒绝被套进一个外层存档事务，避免看似保存了多次、实际直到最后才落盘。
- 3D 职业比赛在任何游戏文件准备或 Steam 调用之前，先保存地图序号、唯一 nonce、十人身份、场馆及冻结选边／难度。准备完成后、调 Steam 之前，再保存调度状态和时间，避免准备时间过长耗尽启动宽限期。外部调用返回后保存结果；即使 Steam 可能已经启动但后续失败，也保留原会话，不把它当作可以回滚的内存变化。
- 开赛信息沿用核心会话生成逻辑，采用显式 `launcher`／`result_reader` 参数，不再替换 Season 模块的全局函数。底层安装检查与换肤适配仍暂存于外部适配器，不宣称这一层已全部去耦合。
- 集中回执支持 `pending → completed`。同 ID 不同内容仍拒绝，完成回执不能退回 pending；查询 pending 返回未知，而非“未执行”。同请求重试只返回确认／当前连接，不重发 Steam。后台重启同样不会自动继续模拟或开赛。
- 普通模拟与快速赛季的玩家 BO 系列现在每张图单独提交，比分、个人数据、阶段事件、随机数进度同批保存。最终地图与系列奖励一起提交。下一图报错时仅回滚该图，已完成地图保留；显式继续从保存的下一图开始。
- 快速赛季保持原有体验：一个界面步仍是整场系列或一次日期推进，各图合并回一个比分展示；决赛选择、休赛期和剧情仍会暂停。内部逐图令牌不覆盖原请求回执，升级前的旧赛季回执在生成新令牌前先校验。
- 从 CS2 切到模拟时，刚完成的真实回传优先：只收下该张地图，不自动模拟下一张。重开当前地图生成新 nonce，旧编号的迟到回传不能结算新图。模式切换的旧游戏请求退役在已保存的生涯状态之后执行，失败不能删除已完成比分；其更通用的外部任务队列仍留在后续清单。
- 实际终止测试子进程（`os._exit`，不执行清理）：开赛信息保存后、调 Steam 前、外部调用后、结果提交后，以及普通／快速第一张图保存后。所有存档和游戏路径都是临时测试副本。另测提交点异常、启动异常、同 ID 撞内容、真实战绩与模拟竞争、老回执升级，以及 BO3／BO5 的逐图写盘顺序。
- 固定种子回归对比中断与不中断的普通／快速系列，恢复后各图比分与十人数据一致。集成脚本已使用冻结的请求 nonce；大回执只比较确认信息，并从独立战报读取完整数据，不再要求确认摘要携带整份报告。

## 外部操作、规则会话与设备共享页 · 第五批

这批仍只修改规范源码仓库，没有部署运行版或更改真实 CS2、存档、GitHub 发布。

- 新增 `services/activity_launch.py`：天梯、自定义、真实训练先保存房间／训练 nonce、冻结请求和集中回执，再准备游戏并启动 Steam，最后保存结果。启动前后的中断都保留原身份；同请求确认不再开赛。失败响应使用失败后的房间状态，不沿用准备阶段的成功连接信息。
